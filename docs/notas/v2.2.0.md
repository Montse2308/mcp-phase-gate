# mcp-phase-gate 2.2.0

*Published on npm on 2026-10-15. In Spanish: [Español](#español).*

The server learns the rest of the MCP protocol: its commands arrive as MCP Prompts, the documents as resources, and it asks you directly before rewriting something. It also gets `doctor`, a way to check an installation.

## What's in it

- **`npx mcp-phase-gate doctor`** and the **`get_orchestrator_status`** tool: an X-ray of the installation (version, variables and where each came from, which prompt wins in each phase, projects, active tasks and findings).
- **`/f1`…`/f5` as MCP Prompts**, served from a single source, so they arrive with every version and nothing has to be copied into any folder.
- **The documents of the tasks as read-only `phase-gate://` resources**, which compatible clients show when you type `@`.
- **Direct confirmations** (MCP elicitation) to rewrite a protected document or start a new project, with a form in your client instead of a `force` that the model could set on its own.
- **The gate warns about the pending items the previous phase left open.**
- **The `PHASE_GATE_*` variables**, with `ORQUESTADOR_*` as an alias that keeps working, and the environment taking precedence over the `.env`. `dotenv` is gone.
- **The tools are served through `McpServer`**, with their annotations (read-only, destructive, idempotent) and static descriptions.
- Fixes: a cancelled confirmation cancels the question, resources don't list what is outside the task, errors use MCP codes, and no notifications go out before `initialize`.

## Español

*Publicada en npm el 2026-10-15.*

El servidor aprende el resto del protocolo MCP: sus comandos llegan como MCP Prompts, los documentos como recursos, y te pregunta directamente antes de reescribir algo. También gana `doctor`, una forma de revisar una instalación.

### Qué trae

- **`npx mcp-phase-gate doctor`** y la tool **`get_orchestrator_status`**: una radiografía de la instalación (la versión, las variables y de dónde salió cada una, qué prompt gana en cada fase, los proyectos, las tareas activas y los hallazgos).
- **`/f1`…`/f5` como MCP Prompts**, servidos desde una sola fuente, así que llegan con cada versión y no hay que copiar nada a ninguna carpeta.
- **Los documentos de las tareas como recursos `phase-gate://` de solo lectura**, que los clientes compatibles enseñan al escribir `@`.
- **Confirmaciones directas** (elicitation de MCP) para reescribir un documento protegido o estrenar un proyecto, con un formulario en tu cliente en vez de un `force` que el modelo podía poner solo.
- **La compuerta avisa de los pendientes que dejó abiertos la fase anterior.**
- **Las variables `PHASE_GATE_*`**, con `ORQUESTADOR_*` como alias que sigue valiendo, y el entorno por encima del `.env`. Se va `dotenv`.
- **Las tools se sirven con `McpServer`**, con sus anotaciones (solo lectura, destructiva, idempotente) y sus descripciones estáticas.
- Arreglos: una confirmación cancelada cancela la pregunta, los recursos no listan lo que queda fuera de la tarea, los errores usan códigos de MCP, y no se notifica nada antes del `initialize`.
