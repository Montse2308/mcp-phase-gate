# mcp-phase-gate 4.0.0

*Published on npm on [REVISAR: the date of the 4.0.0 tag]. In Spanish: [Español](#español).*

4.0.0 changes what you see and what you touch, not the engine. The Studio is redesigned and gains **Settings**, where all the configuration is edited from the browser; the paths of your machine move into `machine.json`; the project has a landing page and a shorter README with guides. The 13 MCP tools (names, arguments and responses), the prompts, the presets, the layers and slots, and the format on disk of documents, receipts and `phase-gate.json` don't change.

## What changes if you upgrade from 3.x

1. **`machine.json` is now version 2, and 3.x can't read it.** It gains `rutas` (`documentacion`, `carpetaDeRepos` and `subcarpetaTareas`): the paths of this machine. 4.0 reads versions 1 and 2 and writes version 2, and the first time Settings or `init` rewrites a version 1 file, it leaves the old one as `machine.json.bak-<date>`. [Going back](#going-back-to-3x) takes two steps.
2. **The paths no longer go in your client's `env` block.** `init` saves them in `machine.json` and takes them out of the entries that already exist (in Claude Code it prints the two commands that redo the entry, and you run them). Settings does the same, with a preview. If you leave `PHASE_GATE_DOCS_PATH` or `PHASE_GATE_REPOS_PATH` in a client, it still wins over `machine.json`, which is how one client can use another Documentation; `doctor` and Settings tell you when that happens.
3. **The language: the environment now wins.** `PHASE_GATE_LANG` beats `idiomaPorDefecto` in `machine.json`. In 3.x it was the other way around, so if you have `PHASE_GATE_LANG` in a client's `env` block, that client now follows it even if you change the default language in `machine.json`.
4. **The Studio has one structure per view, and the theme only changes colours.** The Cockpit mode is gone, and with it the choice between Cockpit and Plain: the Network is a list of rows that expand, a task's phases are six cards and its batches a table. The theme follows your system until you choose one (System, Light or Dark, in Settings or with the button in the top bar). Your saved choice of mode isn't migrated: you start on the system's theme, and the `#?sobrio=` parameter is no longer applied: on the site, such a link just opens the demo, like any other `#?…` link.
5. **Settings is the only place where configuration is edited.** The preset (it was in the Network), the rules (in the Workshop), and the MCP clients and the variables (in the Lookout) moved there; those views show the value and link to it. `eject` stays in the Workshop, because it is about prompts.
6. **The first run opens Settings.** With no Documentation configured, `ui` opens **Settings › This machine** and asks where yours is, instead of showing an empty Network.
7. **The site changed.** The published demo moved to `/demo/` and the root is now a landing page, in English and Spanish. A link with a hash that used to open the demo (`#/tablero/…`, `#red`, `#?lang=en`) redirects to `/demo/` and keeps its view.
8. **If you script the Studio's local API,** the `preset` and `reglas` actions are gone: the new `proyecto` action does what they did, and `equipo` edits `machine.json`.
9. **Commit dates are always UTC.** The Logbook and the exported site read them in seconds since 1970 and write them ending in `Z`, so the exported site is the same whatever the git version or the time zone of the commit.

### Going back to 3.x

3.x doesn't read a version 2 `machine.json`: its `doctor` says `MAQUINA-INVALIDA`, and, if the client no longer has the paths in its `env`, `VAR-FALTA` for the Documentation and the repos folder. Going back takes two steps, and the first one alone isn't enough:

1. Restore the `machine.json.bak-<date>` of version 1 that the Studio or `init` left when they moved the file to version 2.
2. Put the paths back in each client's `env`. In Cursor and VS Code, restore its `mcp.json.bak-<date>` or run 3.2's `init` again. In Claude Code, `claude mcp remove` and `claude mcp add` with their `--env`, which is what 3.2's `init` does.

## What's new

- **Settings**, the sixth view of the Studio: a menu on the left and one page for each thing (this machine, each project, MCP clients, the Studio and the advanced variables). You change several fields, see one diff per file and apply once, with the same preview and fingerprint as always: if the file changed on disk, you get a conflict instead of an overwrite. It warns when a client's `env` overrides `machine.json` and offers to remove it.
- **A new look.** Inter and JetBrains Mono, a blue accent, a light gray background and a slate dark theme, and every state with its own shape and its text, never colour alone.
- **A landing page** at the root of the site, and **a new video** in two pieces: a short GIF for the README and the full MP4.
- **A shorter README, with five guides** in English and Spanish (installation, configuration, the Studio, tools and resources, prompts and layers), and a `CONTRIBUTING.md`.
- **`doctor` and the Studio watch `machine.json`.** `VAR-PISA-MAQUINA` and `LANG-PISA-MAQUINA` report an environment that overrides it, and a change in Settings applies on the next call, with no restart.

## Español

*Publicada en npm el [REVISAR: la fecha del tag 4.0.0].*

La 4.0.0 cambia lo que ves y lo que tocas, no el motor. El Studio se rediseña y gana **Ajustes**, donde toda la configuración se edita desde el navegador; las rutas de tu equipo pasan a `machine.json`; y el proyecto tiene una portada y un README más corto con guías. Las 13 tools de MCP (nombres, argumentos y respuestas), los prompts, los presets, las capas y las ranuras, y el formato en disco de los documentos, los recibos y `phase-gate.json` no cambian.

### Qué cambia si actualizas de la 3.x

1. **`machine.json` pasa a la versión 2, y la 3.x no la lee.** Gana `rutas` (`documentacion`, `carpetaDeRepos` y `subcarpetaTareas`): las rutas de este equipo. La 4.0 lee las versiones 1 y 2 y escribe la 2, y la primera vez que Ajustes o `init` reescriben un archivo versión 1, dejan el viejo como `machine.json.bak-<fecha>`. [Volver atrás](#volver-a-la-3x) son dos pasos.
2. **Las rutas ya no van en el bloque `env` de tu cliente.** `init` las guarda en `machine.json` y las quita de las entradas que ya existen (en Claude Code imprime los dos comandos que rehacen la entrada, y los corres tú). Ajustes hace lo mismo, con vista previa. Si dejas `PHASE_GATE_DOCS_PATH` o `PHASE_GATE_REPOS_PATH` en un cliente, siguen ganando a `machine.json`, que es como un cliente puede usar otra Documentación; `doctor` y Ajustes te avisan cuando pasa.
3. **El idioma: ahora gana el entorno.** `PHASE_GATE_LANG` gana a `idiomaPorDefecto` de `machine.json`. En la 3.x era al revés, así que si tienes `PHASE_GATE_LANG` en el bloque `env` de un cliente, ese cliente ahora lo sigue aunque cambies el idioma por defecto en `machine.json`.
4. **El Studio tiene una sola estructura por vista, y el tema solo cambia colores.** El modo Cabina se va, y con él la elección entre Cabina y Sobrio: la Red es una lista de filas que se despliegan, las fases de una tarea son seis tarjetas y sus lotes una tabla. El tema sigue al de tu sistema hasta que elijas uno (Sistema, Claro u Oscuro, en Ajustes o con el botón de la barra de arriba). Tu elección de modo guardada no se migra: empiezas con el tema del sistema, y el parámetro `#?sobrio=` ya no se aplica: en el sitio, un enlace así solo abre la demo, como cualquier otro enlace `#?…`.
5. **Ajustes es el único lugar donde se edita la configuración.** El preset (estaba en la Red), las reglas (en el Taller), y los clientes MCP y las variables (en el Vigía) se mudaron ahí; esas vistas enseñan el valor y enlazan a él. `eject` se queda en el Taller, porque es de prompts.
6. **El primer arranque abre Ajustes.** Sin Documentación configurada, `ui` abre **Ajustes › Este equipo** y te pregunta dónde está la tuya, en vez de enseñar una Red vacía.
7. **El sitio cambió.** La demo publicada se mudó a `/demo/` y la raíz es ahora una portada, en español y en inglés. Un enlace con hash que antes abría la demo (`#/tablero/…`, `#red`, `#?lang=en`) redirige a `/demo/` y conserva su vista.
8. **Si programas contra la API local del Studio,** las acciones `preset` y `reglas` ya no existen: la nueva `proyecto` hace lo que hacían, y `equipo` edita `machine.json`.
9. **Las fechas de los commits son siempre UTC.** La Bitácora y el sitio exportado las leen en segundos desde 1970 y las escriben terminando en `Z`, así que el sitio exportado sale igual con cualquier versión de git y cualquier zona horaria del commit.

#### Volver a la 3.x

La 3.x no lee un `machine.json` versión 2: su `doctor` dice `MAQUINA-INVALIDA` y, si el cliente ya no lleva las rutas en su `env`, `VAR-FALTA` para la Documentación y la carpeta de repos. Volver son dos pasos, y el primero solo no basta:

1. Restaura la copia `machine.json.bak-<fecha>` de la versión 1 que dejaron el Studio o `init` al pasar el archivo a la versión 2.
2. Devuelve las rutas al `env` de cada cliente. En Cursor y VS Code, restaura su `mcp.json.bak-<fecha>` o vuelve a correr el `init` de la 3.2. En Claude Code, `claude mcp remove` y `claude mcp add` con sus `--env`, que es lo que hace el `init` de la 3.2.

### Qué hay de nuevo

- **`doctor` y el Studio vigilan `machine.json`.** `VAR-PISA-MAQUINA` y `LANG-PISA-MAQUINA` avisan de un entorno que lo pisa, y un cambio en Ajustes vale en la llamada siguiente, sin reiniciar.
